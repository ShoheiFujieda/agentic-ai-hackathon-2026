# デモ動画（約3分）の読み上げ原稿 ver.2 と撮影手順

スライド: [`presentation.pptx`](presentation.pptx)（10枚。8枚が本編、最後の2枚は質疑用の予備）。各スライドのノートにも、同じ原稿が入っている。

## この原稿の作り方（参考: 勝てるピッチの作り方）
- **メインの話は、あなた自身の体験**（大学生として奨学金を探したとき、AIが5年前の募集を拾ってきた・すぐ見つかるものを漏らした）。ここが一番の説得力なので、スライド1〜2で、自分の言葉で、ゆっくり話す
- **目的は「審査員を動かす」こと**: 「使ってみたい」「安全に使えそうだ」と思ってもらう。説明ではなく、語りかける**演説**にする
- **冒頭で顔を上げてもらう**: 最初の一言は、問いかけ（「間に合わなかった経験、ありませんか？」）
- **流れは、問題 → 数字 → だから変える → 見せる → 安全 → 証拠（正直に）→ 一言**（審査基準の順: ①課題と有効性 → ②自律性・安全 → ③実装品質）。冒頭30秒で「課題→数字で示す効果→安全装置」まで届ける
- **短い文**にして、言いにくいところは削る（読むのではなく、話す）。数字は少なく、強い1つ（34件中12件）を立てる
- **スライドの文字と、原稿は、少し違う言葉**にする（そのまま読まない）。1スライド1メッセージ
- 限界は隠さず、1行で言い切る（スライド7）。信頼につながる

### 記号の読み方（抑揚のつけ方）
- **★**: そこを強く、ゆっくり（その言葉の前に、一拍おく）
- **【間】**: 約1秒、止まる（聞き手が考える時間。ここを守ると、伝わる）
- **／**: 短い息継ぎ（0.3秒）。文の途中で、声を落として、つなぐ
- **――**: 溜める。次の言葉を、低く、はっきり
- 疑問文（「間に合わなかった経験、ありませんか？」「聞けばいい？」）は、語尾を上げて、**聞き手の顔を見る**つもりで
- 数字（34件、12件、2件、10件…）は、言う前に一拍、言ったあとに一拍
- スライド4・5の（　）は動画の状況のメモ。読まない。画面の動きに合わせて、話すタイミングをずらす

## 練習のしかた（ストップウォッチで）
1. **15〜30秒のパーツ**ごとに練習する（スライド1枚が、1パーツ）。全体で測っても直しにくい
2. 声に出して、**言いにくい所・舌が回らない所**を、1文字単位で直す（原稿を「磨く」）。直したら、`narration/script.json` と、このファイルの表を、そろえる
3. スマホで**録音して聞く**。抑揚が無いと感じたら、★と【間】を増やす
4. 全体を通して、約2分40秒〜3分に収まるか測る。長い時は、スライド3・4の言い回しを削る
5. デモ動画の部分（スライド4・5）は、動画を流しながら、原稿を話す。動画を先に見て、画面の動きに合わせて、話す位置を決めておく

## 事前に撮るデモ動画（2本）
撮影前に、同じ条件で1回検索して、キャッシュを温めておく（`powershell -File scripts/warm_prod.ps1`。約30秒で結果が出る）。
- **デモ①（約50秒、スライド4）**: 公開URLにログイン → 「入力例を入れてみる」→「奨学金を探す」→ 結果の表（応募できる／要確認／未確認／募集終了）→「確認すること」→ 立場を「卒業後（社会人）」・目的を「研究」に替えて再検索 → 結果を保存 → CSV
- **デモ②（約35秒、スライド5）**: チャットで「『（奨学金の名前）』を共有リストに追加したい。公式ページは https://… 」と入力 → 承認待ち → 確認ダイアログで許可 → 完了 → 右の「操作の記録」
- 画面は1920×1080、ブラウザの拡大は100〜125%。個人情報や、パスワードが映らないようにする（ログイン後の画面から撮る）。

## スライドへの動画の入れ方
1. スライド4（デモ①）、スライド5（デモ②）を開く
2. ［挿入］→［ビデオ］→［このコンピューター上のビデオ］で動画を選ぶ
3. 点線の枠に重ねて、サイズを合わせる。枠（点線の四角）は削除してよい
4. ［再生］タブ →［開始］を「自動」にすると、スライドが出たら再生される（自分の声を重ねるなら、動画の音量をミュート）
5. 全体を、画面録画（PowerPoint の［スライド ショー］→［記録］、または OBS）で撮り、約3分に収める
6. YouTube に「公開」でアップロードする（提出の条件）
